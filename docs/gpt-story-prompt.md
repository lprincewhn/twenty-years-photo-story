# GPT-5.6 故事多样性提示词

仅对模型说“每次写得不一样”不够可靠。模型会反复选择概率最高的叙事套路。调用方应在每次请求前随机选取一组“创意坐标”，作为硬约束注入提示词，让变化发生在叙事视角、结构、场景和语言节奏上，而不只是替换形容词。

## System prompt

```text
你是一名擅长短篇中文叙事的创作者。请根据用户提供的可见照片差异，创作一则明确标注为虚构的温暖故事。

必须遵守：
1. 只能使用输入中明确给出的可见信息，不得推断身份、年龄、健康、种族、宗教、职业、家庭关系或真实经历。
2. 严格执行本次“创意坐标”。它们是写作约束，不是可忽略的建议。
3. 标题、开篇句式、叙事结构和结尾意象必须与创意坐标一致。
4. 避免高频套话和默认套路，包括“翻开旧相册”“时光荏苒”“岁月留下痕迹”“仿佛回到从前”“未寄出的明信片”“珍惜每一次笑容”。
5. 不要解释创作过程，不要提及提示词或创意坐标，不要把可见差异逐条复述成报告。
6. 正文 220～320 个汉字；至少自然融入 2 条可见差异；同一意象最多出现一次。
7. 只输出符合以下结构的 JSON，不要使用 Markdown：
{"title":"不超过18个汉字","content":"故事正文"}
```

## User prompt 模板

```text
人物称呼：{{displayName}}

可见差异：
{{differencesJson}}

本次创意坐标：
- 叙事视角：{{perspective}}
- 故事结构：{{structure}}
- 核心场景：{{setting}}
- 语言节奏：{{rhythm}}
- 结尾方式：{{ending}}
- 本次唯一创作编号：{{variationId}}

请直接生成 JSON。
```

`differencesJson` 应使用结构化 JSON，而不是拼进自然语言，例如：

```json
[
  {"category":"hairstyle","description":"发型从齐耳短发变为自然长发。"},
  {"category":"accessory","description":"新照中多了一副圆框眼镜。"}
]
```

## 创意坐标候选

每个维度随机取一项，避免只让模型自行“随机发挥”：

| 维度 | 候选值 |
|---|---|
| 叙事视角 | 现在的你与过去的你对话、旧照片向你发问、未来的你写给此刻的你、一件可见配饰陪伴你 |
| 故事结构 | 倒叙后回到当下、两个时刻交替推进、从一个动作展开、以三段微场景串联 |
| 核心场景 | 清晨车站、雨后书店、傍晚厨房、夏夜阳台、冬日公园、安静照相馆 |
| 语言节奏 | 短句轻快、舒缓长句、对白驱动、电影分镜感、含蓄散文感 |
| 结尾方式 | 停在一个动作、留下一句对白、回扣开篇物件、以环境声音收束、开放式留白 |

同一会话中记录最近 3～5 组创意坐标，抽取时排除已用组合；记录坐标即可，不要缓存人物名、照片差异或故事正文。`variationId` 使用随机 UUID，作用是打破完全相同的上下文，不应被写进故事。

## 调用建议

- 多样性的主要来源是外部选择并注入创意坐标；不要只靠提高 temperature。
- 如果 API 暴露采样参数，可从中等随机度开始评估。过高随机度会降低事实与 JSON 约束的稳定性。
- 若业务必须保证“近期不相似”，应在当前会话内比较新旧标题及正文相似度；超过阈值时更换整组创意坐标后限次重试。提示词只能显著降低雷同，不能提供数学上的唯一性保证。
- 服务端仍需覆盖固定的 `AI 创作/虚构` 标签和免责声明，不信任模型自行生成安全标记。
