# 技术研究与决策

## 1. 前端与构建工具

**决定**：React + Vite + TypeScript。  
**理由**：状态步骤明确、生态成熟、移动浏览器支持良好；Vite 配置少且生产构建简单。  
**替代方案**：纯原生页面依赖更少，但相机轨道、对象 URL 和多状态清理更易遗漏；Next.js 对本无状态 MVP 过重。

## 2. 服务端框架与上传

**决定**：Express 5 + Multer `memoryStorage`。  
**理由**：multipart 支持成熟，可明确限制单文件和大小；内存 Buffer 能在请求结束时主动清零。  
**替代方案**：Fastify 性能更高但本项目吞吐不是瓶颈；Base64 JSON 会额外膨胀约三分之一。

## 3. 相机兼容策略

**决定**：优先 `navigator.mediaDevices.getUserMedia({ video: { facingMode: "user" } })`，始终保留 `<input type="file" accept="image/*" capture="user">`。  
**理由**：iOS/Android 权限、WebView 能力差异大；文件输入是最可靠的渐进增强回退。相机仅在安全上下文可用，生产必须 HTTPS。

## 4. provider 边界

**决定**：分别定义 `FaceMatchProvider`、`DifferenceProvider`、`StoryProvider`，由服务端组合。  
**理由**：三项能力可能来自不同供应商，且隐私、超时和错误码不同。依赖注入允许契约测试与逐个替换。  
**替代方案**：单一“分析 provider”代码更短，但耦合供应商、难以过滤越界差异。

## 5. 匹配阈值

**决定（Azure Face 实测后修订）**：默认阈值 0.6，范围限制为 0.50～0.99；分数等于阈值视为达到。Azure Identify 粗筛默认 0.5 且必须严格低于业务阈值。
**理由**：阈值必须由业务验证后配置，MVP 数值仅用于模拟；双重检查确保 provider 不直接给身份结论。UI 同时展示百分比分数和阈值。  
**注意**：上线真实识别前必须使用经授权、代表性数据校准，记录误匹配/漏匹配；不得把分数表述为身份事实。

## 6. 差异与生成安全

**决定**：差异使用枚举允许列表，故事使用固定 AI 标签与免责声明。  
**理由**：只靠提示词无法保证边界；服务端结构化过滤是必要的第二道防线。任何不认识的差异类别均丢弃，空列表使用安全兜底文案。

## 7. 照片生命周期

**决定**：前端仅持有 `File`、短期对象 URL 或相机画布 Blob；服务端仅持有请求 Buffer，处理后 `fill(0)`。  
**理由**：MVP 无需历史记录。无数据库、无文件目录、无分析缓存、无内容日志，显著减少泄露面。JavaScript 垃圾回收无法保证物理内存立即归还，因此清零是尽力而为，进程/基础设施仍需按受控敏感工作负载管理。

## 8. 真实 provider 接入

**决定**：密钥只由服务端环境变量读取，适配器实现同一接口并设置超时；不得在失败时静默使用 mock 冒充真实结果。  
**理由**：避免密钥暴露与结果来源混淆。可在明确的开发 `PROVIDER_MODE=mock` 中使用 mock，生产配置失败则启动失败或返回可解释错误。
