# 功能规范：“二十年前与现在”照片故事 MVP

**功能分支**：`feature/SVHW-16-photo-story-mvp`  
**创建日期**：2026-08-29  
**状态**：已批准实施  
**关联事项**：SVHW-16

## 背景与范围

用户在移动端阅读隐私说明并明确授权后，拍摄或选择一张当前照片。系统在授权示例人物库中寻找达到阈值的候选人，仅描述新旧照片中可见的非敏感差异，并生成显著标为虚构的温暖小故事。本 MVP 用无密钥 mock provider 完成端到端演示，并保留替换真实服务的稳定边界。

不在范围内：注册登录、照片持久化、真实人物数据采集、身份认证结论、敏感属性推断、社交分享、付费能力和模型训练。

## 用户场景与验收

### 用户故事 1：知情开始体验（优先级 P1）

作为首次访问者，我希望先了解照片用途、保留方式和 AI 内容性质，再主动决定是否开始。

**独立验收**：未勾选授权时不能进入拍摄；勾选后可以继续；页面明确说明默认不留存现场照片、人物库为授权示例、故事为 AI 虚构。

**验收场景**

1. **假如**用户未授权，**当**点击“开始拍照”，**那么**焦点移到中文授权提示，且不请求相机权限。
2. **假如**用户已授权，**当**点击“开始拍照”，**那么**进入拍摄步骤并展示相机与相册回退入口。

### 用户故事 2：拍摄、预览与确认（优先级 P1）

作为移动端用户，我希望拍照或从相册选择，预览后可以重拍或确认上传。

**独立验收**：支持 `getUserMedia`；API 不可用、权限拒绝或启动失败时仍可使用 `capture="user"` 的文件输入；确认前不上传。

**验收场景**

1. **假如**浏览器允许相机，**当**用户开启并拍摄，**那么**展示当前帧预览并停止摄像头轨道。
2. **假如**用户拒绝相机，**当**权限请求失败，**那么**展示中文解释和相册选择按钮。
3. **假如**已有预览，**当**用户选择“重拍”，**那么**释放本地预览 URL 并返回拍摄入口。

### 用户故事 3：获得可信结果（优先级 P1）

作为参与者，我希望看到旧照、当前照片、匹配置信度、可见差异和虚构故事，同时不会被误导为真实身份或经历。

**独立验收**：达到阈值才显示人物名称；置信度、阈值与结论同屏；差异限于允许类别；故事上方及结果摘要中标有“AI 创作/虚构”。

**验收场景**

1. **假如**最高分不低于阈值，**当**分析完成，**那么**显示示例旧照、新照、本次分数、阈值、非敏感差异及 AI 虚构故事。
2. **假如**最高分低于阈值，**当**分析完成，**那么**只显示“未找到足够可信的匹配”，不得显示候选身份结论。
3. **假如**体验完成，**当**用户点击“重新体验”，**那么**清理预览、结果和错误，并回到授权步骤。

### 用户故事 4：理解并恢复失败（优先级 P1）

作为遇到问题的用户，我希望知道发生了什么、是否可重试以及下一步该做什么。

**独立验收**：无效图片、无人脸、多人脸、未匹配、请求过大、网络错误和 provider 故障均有不同中文状态；可重试项提供返回拍摄或再次上传操作。

## 功能需求

- **FR-001**：系统必须在请求相机或读取/上传照片前取得未预选的显式授权。
- **FR-002**：系统必须支持相机实时拍照和文件选择回退，且提供预览、重拍与确认。
- **FR-003**：服务端必须验证授权标记、图片 MIME 和 6 MiB 大小上限，图片仅在内存处理。
- **FR-004**：人脸匹配、可见差异、故事生成必须是三个可替换 provider 接口。
- **FR-005**：mock provider 必须无密钥可运行，并能演示成功、无脸、多人脸、未匹配和 provider 故障。
- **FR-006**：匹配阈值必须可配置，默认 0.82；响应必须含分数、阈值和置信级别；低于阈值不得返回身份结论。
- **FR-007**：差异类别只能为发型、服饰、表情、配饰；输出必须经过服务端允许列表过滤。
- **FR-008**：故事必须带结构化 `AI 创作/虚构` 标签和不代表真实经历的免责声明。
- **FR-009**：人物库只能包含授权状态、来源说明和占位/授权资源；MVP 不得提交未授权真实人物照片。
- **FR-010**：服务端不得把照片或人脸特征写入磁盘、数据库和日志，并在请求结束时清零可控内存缓冲区。
- **FR-011**：错误响应必须包含稳定代码、中文消息、中文解释、可重试标记和请求标识。
- **FR-012**：移动端必须有语义化标题、标签、状态播报、键盘焦点、清晰焦点样式、足够触控面积和减少动画支持。
- **FR-013**：必须提供健康检查，且不暴露密钥、人物资料或运行时内部错误。
- **FR-014**：前端不得保存照片到 localStorage、IndexedDB 或服务端会话；当前照片只以页面生命周期内的对象 URL 展示。

## 非功能需求

- 首屏压缩后静态资源在常规 4G 网络可合理加载；不引入大型 UI 框架。
- API 处理为无状态，mock 模式下单次请求目标 2 秒内完成。
- 支持当前两个主要版本的 iOS Safari、Android Chrome 和现代桌面浏览器。
- 生产部署必须使用 HTTPS；CORS 来源显式配置；密钥仅由服务端环境变量读取。

## 关键实体

- **人物条目**：内部标识、展示名、旧照地址、授权状态、来源说明。
- **匹配判定**：分数、阈值、置信级别、是否达到阈值；仅达到阈值时关联人物。
- **可见差异**：允许类别、中文描述、证据范围提示。
- **虚构故事**：标题、正文、固定 AI 标签、免责声明。
- **体验结果**：请求标识、保留说明、匹配判定、差异列表、虚构故事。

## 成功标准

- **SC-001**：全新环境执行文档中的安装和启动命令可在无 provider 密钥时完成成功体验。
- **SC-002**：所有规定错误场景均返回不同稳定代码并在界面显示中文恢复建议。
- **SC-003**：自动化测试覆盖三个 provider、阈值等于/高于/低于边界、API 校验与前端核心状态。
- **SC-004**：lint、类型检查、测试和生产构建全部通过。
- **SC-005**：代码库搜索不到真实 provider 密钥、未授权人物照片、照片落盘路径或客户端密钥读取。
- **SC-006**：使用键盘可完成授权、文件选择后的确认、重拍和重新体验，动态状态可被辅助技术播报。

## 假设

- mock 的“识别”是产品流程模拟而非生物识别能力验证。
- 示例旧照为自制 SVG 插画，不构成真实人脸或真实身份材料。
- 当前照片在浏览器中只保留到重拍、重新体验或页面关闭。
